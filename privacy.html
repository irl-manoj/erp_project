Privacy Policy

Applies to this educational demonstration application. Last updated: 27 November 2026.
Important: this is an educational project, not an official BIT Mesra service. It includes a real Express API, SQLite database, and local file uploads, but its bundled accounts and academic records are demonstration data. Do not upload confidential or official student records to an unapproved deployment.

1. What this application is

The MCA Academic Dashboard demonstrates student and teacher workflows for attendance, assessment marks, assignments, submissions, and academic progress. The bundled accounts and sample records are for testing. A department must approve any real deployment and data processing before use.

2. Information processed by the application

  • Login identifiers and passwords are sent to the same-origin API for verification. Passwords are stored as bcrypt hashes, not plaintext.
  • Authenticated profile, attendance, assessment, assignment, and submission records are stored in the server-side SQLite database.
  • Assignment attachments and student submissions are stored in private server folders and are returned only through authenticated download routes.
  • The application uses a signed, 12-hour HttpOnly cookie where supported, with a short-lived bearer-token fallback in sessionStorage for embedded preview browsers. A small user display cache is kept in localStorage; academic records are not stored in browser storage.

For a local development setup, the database is in data/academic.sqlite and uploaded files are under uploads/. A hosted deployment may use different storage. The operator must protect, back up, and delete stored data according to approved institutional policy.

3. Browser storage and sessions

The application stores the signed-in user's display profile under mca_current_user in localStorage. A short-lived authentication token may be stored in sessionStorage when embedded preview browsers do not send the HttpOnly cookie. Both mechanisms expire or are cleared when the user logs out. Clearing browser site data does not delete records already stored on the server.

4. Third-party resources

The pages load open-source libraries and fonts from public CDNs (Bootstrap, Chart.js, Font Awesome via jsDelivr; Google Fonts). A request to these providers is made by your browser when a page loads, and standard web requests include technical details such as your IP address and user agent. The library code is not modified and does not collect information on our behalf. If you would rather avoid this, the files can be self-hosted with no functional changes.

5. Children and sensitive information

This project is not designed for children or for handling sensitive institutional records. Use only the sample data unless the responsible institution has formally reviewed and approved the deployment.

6. Your choices

  • Log out when you finish using a shared device.
  • For a local development copy, the project operator can remove the SQLite database and upload folders to delete server-side demo data.
  • For a hosted copy, contact its operator to request information about data retention or deletion.

7. Deployment and applicable requirements

This policy describes the current demonstration implementation, not a complete institutional privacy program. A public deployment requires an approved operator, retention and deletion procedures, security controls, backups, and a policy reviewed for applicable Indian law, including the Digital Personal Data Protection Act, 2023. Update this notice before processing real student data.
